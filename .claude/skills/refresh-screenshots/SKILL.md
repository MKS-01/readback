# refresh-screenshots — update project images after UI changes

Run this after any CLI or dashboard UI change that affects what's shown in the
README or landing page screenshots. The user drops fresh captures into a folder
and this skill maps them to the right `docs/media/` slots.

---

## 1. Collect screenshots from the user

Ask the user for a folder path containing the new screenshots. Common location:
`~/Desktop/ui/` or wherever they dumped their captures.

```bash
ls -la <folder>/
```

The screenshots are typically `.heic` (macOS) or `.png`. Map each one to a
**media slot** by examining its content:

| Media slot | What it shows | File |
|---|---|---|
| `cli-home.png` | Input screen — wordmark, hint line, input box, status line | `docs/media/cli-home.png` |
| `cli-model.png` | `/model` list — models with fit verdicts and recommendation | `docs/media/cli-model.png` |
| `cli-player.png` | Player screen — title, progress bar, transcript (if visible) | `docs/media/cli-player.png` |
| `dashboard.png` | Dashboard — card list with inline player, landscape | `docs/media/dashboard.png` |
| `dashboard-mobile.jpg` | Dashboard on mobile viewport | `docs/media/dashboard-mobile.jpg` |

Not every slot needs updating every time — only replace what changed.

## 2. Convert and optimize

HEIC files must be converted to PNG (CLI screenshots) or JPG (mobile shots).
Optimize file size without visible quality loss.

```bash
# HEIC → PNG (CLI / dashboard desktop)
sips -s format png <source>.heic --out docs/media/<slot>.png

# Downscale if wider than needed (README renders at 640/720px max)
# CLI shots: 640px display width → capture at ~1280px retina is fine
# Dashboard: 720px display width → capture at ~1440px retina is fine
sips --resampleWidth 1280 docs/media/cli-home.png
sips --resampleWidth 1440 docs/media/dashboard.png

# HEIC → JPG for mobile shots (smaller file size)
sips -s format jpeg -s formatOptions 80 <source>.heic --out docs/media/dashboard-mobile.jpg
sips --resampleWidth 520 docs/media/dashboard-mobile.jpg
```

Check file sizes — aim for:
- CLI PNGs: < 1 MB each
- Dashboard PNG: < 500 KB
- Mobile JPGs: < 100 KB

```bash
ls -lh docs/media/*.png docs/media/*.jpg
```

## 3. Verify references

All images in `docs/media/` are referenced from multiple places. Verify none
are broken after the replacement.

```bash
# README references
grep -n 'docs/media/' README.md

# Landing page references (uses relative media/ path — files are copied at deploy)
grep -n 'media/' src/landing-page/index.html

# Pages workflow — must list every media file in BOTH paths: and cp:
grep -A20 'paths:' .github/workflows/pages.yml | grep media
grep -A10 'cp.*media' .github/workflows/pages.yml
```

### If adding a NEW media file

Three places need updating:

1. **`README.md`** — add the `<img>` tag at the right spot
2. **`src/landing-page/index.html`** — add it to the stepper or relevant section
3. **`.github/workflows/pages.yml`** — add to BOTH the `paths:` trigger list
   AND the `cp` copy list (the comment at the top of the workflow warns about this)

## 4. Preview

The README renders on GitHub — verify images display correctly at their set widths:

```bash
# Check the display widths set in README
grep -oP 'width="\d+"' README.md | sort -u
```

Current display widths:
- CLI screenshots: `width="640"`
- Dashboard: `width="720"`
- Mobile: `width="260"`
- Wordmark: `width="487"`

For the landing page, the images render inside a fixed-height `demo-frame`
(460px desktop, 300px mobile) with `object-fit: contain` — verify new images
don't letterbox badly:

```bash
# Check captured image dimensions
sips -g pixelWidth -g pixelHeight docs/media/cli-home.png
```

Landscape screenshots (wider than tall) work best in the stepper frame.

## 5. Commit

```bash
git add docs/media/<updated files>
git commit -m "docs(media): refresh screenshots for <what changed>"
```

The landing page deploys automatically via `pages.yml` when these files change
on main (after the PR merges).
