How readback works

June 2026 · notes/02

readback is two pieces: a small Python server that does the work, and a terminal client that talks to it over a WebSocket. The CLI auto-starts the server if one isn't running and shuts it down on exit — to you it's a single command. From a pasted URL to audio in your shell, a read goes through four stages.

## 1. Extract

The article body is pulled out of the page with trafilatura, with a browser-agent fallback for sites that block the default one. Then a light scrub removes the things you'd never want read aloud — bare URLs, citation markers like [12], stray whitespace.

## 2. Summarize (optional)

In Summary mode, one call to a local LLM (via Ollama, gemma4:26b by default) rewrites the article as a spoken explanation — the kind of summary a friend would give you, not an abstract. Full mode skips this entirely; no LLM is involved and the article is read verbatim. You can switch the model from the CLI with /model, which checks each installed model against your Mac's RAM before you commit.

## 3. Synthesize

The text is split into sentence-aware chunks and each one is synthesized with CSM-1B — Sesame's conversational speech model — running on the GPU through MLX. Two details carry the perceived quality: every chunk is silence-trimmed (CSM likes to leave long dramatic pauses), and the chunks are joined with small, even gaps so the read flows instead of halting.

Progress streams back over the WebSocket the whole time — phases first (fetching, summarizing, synthesizing), then a per-chunk counter — so the terminal shows exactly where a long read is.

## 4. Play

The finished WAV is served over HTTP and played with afplay. The player is a real one: pause, seek ±5 s (despite afplay having no transport — the CLI slices the WAV and relaunches), and in Summary mode a transcript that highlights word by word in sync with the voice.

## The one constraint that shapes it all

MLX binds its GPU stream to the first thread that touches it, so all model work runs on a single dedicated thread and read jobs queue naturally — one article synthesizes at a time, and a cancel mid-job actually stops the work. It's a small design, on purpose: one server, one socket, one pipeline.
