## Features

  • ▮ 100% offline

    Extraction, summarization, and speech all run on-device — MLX on Apple Silicon. No accounts, nothing phoning home.

  • ▮ A voice worth listening to

    CSM-1B neural TTS (Sesame). Two built-in reading voices, clone any voice from a short clip, or LoRA fine-tune for more fidelity.

  • ▮ Full or Summary mode

    Hear the article verbatim, or let a local LLM (Ollama) rewrite it as a spoken explanation first — any model on your machine works; /model lists them with a RAM-fit check.

  • ▮ A real player — plus a library

    Pause, seek ±5 s, and a transcript that highlights word by word in sync with the voice — in your shell, or the web dashboard. Every read is saved to replay anytime.

## Quick start

macOS on Apple Silicon · Python 3.10–3.12 · Bun · Ollama (Summary mode only)

# 1. Ollama for Summary mode (skip for Full mode)
ollama pull gemma4:26b   # any chat model works — we ran gemma & qwen

# 2. Install the server
git clone https://github.com/MKS-01/readback.git && cd readback
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e .

# 3. Build the terminal client → ~/.local/bin
cd src/cli && ./install.sh && cd ..

# 4. Read something
readback-cli

Paste a URL, watch it synthesize, audio plays in your shell. Full docs in the README.

## How it took shape

The big turns and decisions — not every commit.

  1. 2015 · the itch

    A duct-tape voice loop

    Tinkering with speech-to-text → text-to-speech since college. The part I kept wanting was the listening, not the talking.

  2. start · local-tts

    A real-time voice assistant

    Mic capture, wake-words, a full live cascade — dual ASR, Smart-Turn, a neural voice. Useful, but the conversation was never the point.

  3. v0.8 · the pivot

    From assistant to reader

    Cut the entire live cascade. Switched to CSM-1B and one job: URL → article → audio, offline. Renamed local-tts → readback.

  4. v1.0 · terminal

    A client worth living in

    A Bun + Ink CLI over a WebSocket — seekable player, a transcript that highlights word by word. It belonged in the shell.

  5. v2.0 · subtract

    CLI-only

    Removed the web frontend entirely; leaned the package down to a clean src/ layout. Voice quality over surface area.

  6. v3.0 · the library

    The web returns — as replay

    Every read persists to SQLite; a Vue dashboard searches & replays past audio. Generation stays heavy and on-demand, replay stays light and model-free.

## Architecture

The concepts that shape it — small on purpose: one server, one socket, one pipeline.

  • Client / serverThe CLI (Bun + Ink) is a pure WebSocket client — it auto-spawns the FastAPI server, supervises it, and adds zero server code.
  • One pipelinefetch ▸ extract (trafilatura) ▸ [summary] ▸ chunk ▸ synth ▸ WAV — progress streams per chunk over /ws.
  • One GPU threadMLX binds its Metal stream to a single thread, so read jobs queue naturally and a cancel actually stops the synthesis mid-job.
  • Voice = a clipCSM-1B conditions on a short reference clip + its transcript — swap the clip, swap the voice; LoRA fine-tune for more fidelity.
  • Bring your LLMSummary mode runs on whatever Ollama models you have installed — we ran gemma & qwen; /model lists yours with a RAM-fit verdict.
  • Generate ↔ replayEvery read persists to a stdlib-SQLite library; a separate Vue dashboard searches & replays past audio — model-free, so generation stays heavy/on-demand while replay stays light.
  • Offline by designWeights download once, then nothing leaves the machine — synthesis on Metal, playback via afplay, the WAV saved locally.
